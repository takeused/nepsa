# 브라우저 조작 검증 — 2026-09-06

대상: `vinext dev` (localhost:3000), 데이터는 `docs/example-portfolio.json`(가상 과제 14개)을 앱의 **백업 불러오기**로 적재.

## 검증 방식과 한계

브라우저 창이 배경에 있어 `document.visibilityState`가 계속 `hidden`이었다. 그 상태에서는
픽셀 클릭·키 입력이 React 핸들러에 도달하지 않았고 Base UI 팝업(Select)이 열리지 않았다.
그래서 버튼은 `element.click()`, 입력은 네이티브 setter + `input` 이벤트로 조작했다.
앱의 실제 핸들러·상태·localStorage 경로는 모두 실행되지만 **사람이 마우스로 누른 것과 같지는 않다.**
아래 "미검증"은 이 제약 때문에 남은 항목이다.

## 2차 — 크롬 창을 앞으로 가져온 뒤 (같은 날)

창이 보이게 되자 `visibilityState`가 `visible`이 되었고 드롭다운이 곧바로 정상 동작했다.
**앞서 팝업이 열리지 않던 것은 배경 창이라는 환경 조건 때문이며 앱 결함이 아니다.**

| 항목 | 결과 |
| --- | --- |
| 과제 유형 드롭다운 | 실제 클릭으로 열림, 원천기술형 선택 시 통계·매트릭스 캡션 전환 |
| 정성지표 점수 드롭다운 | 시장경쟁강도 5점 → 1점 실제 클릭 선택 → 위험 60.00 → 35.00, B1 → A1, localStorage에 `competition: 1` 저장 |
| 백업 교체 대화상자 | 실제 "확인" 클릭으로 11개 → 14개 교체 |
| 화면 렌더링 | 라이트 테마, 매트릭스, 편집기 정상 표시 |
| 인쇄 미리보기 | 사용자가 직접 확인 — 페이지에 제대로 들어감 |

## 남은 미검증

- **모바일 폭(375~420px).** 크롬 창이 최대화 상태라 `resize_window`가 무시되었고, Claude 브라우저 패널은 폭을 837px 아래로 낮추지 못했다. 837px에서는 가로 넘침이 없었다. 창 최대화를 해제하면 재확인 가능하다.
- **Excel에서의 CSV 열기.** 파일(`NEPSA-상세평가.csv`, UTF-8 BOM)은 사용자에게 전달했다.

## 주의

- `window.print()`는 모달 인쇄 미리보기를 띄우며 그동안 해당 탭의 렌더러가 멈춘다. 자동화 중에는 인쇄 버튼을 마지막에 누르거나 피하는 편이 좋다.
