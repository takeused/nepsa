# 전반 로직 검토 · 2026-09-05

## 검토 범위

정량 채점, 100점 환산, 기업주관·원천기술형 등급 및 순위, 정성 분포, 저장·복원·예시 추가와 입력 검증을 검토했다. 선택한 산식과 IP 반올림 정책은 변경하지 않았다.

## 발견 및 수정

1. **기술격차 소수점 경계:** `83.1−63.1`은 JavaScript에서 20보다 조금 작아 3점 대신 2점이 될 수 있었다. 목표와 현재 수준을 입력 숫자의 십진 표현으로 비교하도록 수정했다. 단순 덧셈 비교도 `2.24+15`에서 오차가 나므로 정확한 십진 스케일 비교를 사용한다. 임의의 epsilon으로 실제 경계 아래 값을 끌어올리지 않는다. 브라우저의 Number로 표현할 수 있는 정밀도 범위 내에서 동작한다.
2. **다른 탭의 작업 덮어쓰기:** 마지막으로 읽거나 저장한 문자열과 현재 저장값을 저장 직전에 대조한다. 다른 탭이 변경했다면 저장을 중지하고 현재 작업 백업·새로고침을 안내한다. 동일 내용의 중복 저장은 허용한다.
3. **수정한 원문 예시의 선택 오류:** CCC의 유형을 원천기술형으로 바꾸고 예시를 불러오면 기업주관형 화면에서 존재하지 않는 과제를 선택했다. 현재 유형에 실제로 있는 과제를 선택하도록 수정했다. 불러온 예시의 근거를 수정해도 원본 자료와 참조를 공유하지 않는다.
4. **내보내기·가져오기 용량 불일치:** 복원은 5MB로 제한하면서 내보내기는 제한이 없었다. 저장·백업 생성에도 같은 UTF-8 바이트 한도를 적용하고, 내보내는 JSON의 직렬화 형식을 일치시켰다. 제한 초과 시 마지막 정상 저장본을 보존한다.
5. **채점 입력 일관성:** 가져오기 검사 없이 호출되어도 비정수 지표는 채점하지 않으며, 1~5 범위를 벗어난 정성 점수는 유효 응답으로 집계하지 않는다.

- 유효 영역 내 정수 좌표 전체에서 기대성과 증가·위험 감소 시 영역 우선순위가 악화되지 않음을 확인했다.
- 소수 둘째 자리의 유효 기술수준 전체에 대해 기술격차 기준점과 바로 아래를 검사했다. 고정밀 경계 아래 값과 지수 표기도 확인했다.
- 저장 충돌, 잘못된 입력, 저장소 쓰기 실패, 용량 초과, 예시 한도와 선택 상태를 검증했다.
